The Problem

"Prove this AI decision wasn't tampered with."

A bank approves a loan using an AI system. A customer later disputes the decision. The regulator asks a simple question: how do you know your own team didn't quietly edit the record after the fact? A database row isn't an answer — whoever controls the database can edit it. Praman replaces "trust us" with a chain of events that makes editing detectable within milliseconds.

Why this is live now, not hypothetical: DPDP Rules 2025 were notified 14 Nov 2025, with enforcement phasing through Nov 2026 and May 2027 — the Consent Manager framework is being operationalised between June–Aug 2026, right now. RBI's FREE-AI Framework (released Aug 2025) requires every regulated entity to run a board-approved AI policy with lifecycle governance. Both created a live compliance gap that most banks are still solving with spreadsheets.

Why Not Blockchain

Blockchain solves consensus — useful when no single party is trusted. A bank is already the trusted party; it doesn't need 50 computers to agree on a loan decision. It needs tamper-evidence, which a Merkle tree gives you for a fraction of the cost.
Product Maturity

What's built, what's honest, what's next

This is an MVP built in seven days. Rather than blur the line between working and aspirational, every stub is disclosed — in the code, in LIMITATIONS.md, and here. Click through:

Append-only event ledgerLive
A Postgres trigger physically blocks UPDATE and DELETE. Records cannot be quietly rewritten, even by a database administrator.
Enforced at the database layer, not application logic — an app-layer guard is bypassable by anyone with direct DB access, which is exactly the threat model here.
HMAC chaining across both modulesLive
Every event is cryptographically linked to the one before it. Governance decisions from Module 2 chain into the same ledger as privacy events from Module 1.
domain/hashing.py — the client holds the key, so the vendor cannot forge an event even with full database access.
Merkle tree, root, and inclusion proofsLive
Prove one specific event is in the record without disclosing any of the others.
domain/merkle.py — leaves prefixed 0x00, internal nodes 0x01, domain-separated to close the second-preimage weakness in the original Bitcoin construction (CVE-2012-2459).
Ed25519 signingLive
The root is signed. Anyone holding the public key can verify it independently — including a regulator, without trusting the bank.
Behind a Signer port. ECDSA P-256 and an HSM/KMS path are documented alternatives; swapping is one branch in factories.py.
BSA §63 certificate generationLive
Produces a PDF in the "Certificate by Party" format — identifying the record, how it was produced, and its hash value and algorithm.
BSA 2023 came into force 1 July 2024, replacing the Indian Evidence Act 1872. §63 recognises two certificate types; this generates the party certificate, leaving Part B for the customer's CTO to attest.
Autonomy tiers + delegation ceilingsLive
Four tiers from read-only to unrestricted. An agent cannot spawn a second agent with more authority than it holds itself.
Blocking privilege escalation through delegation is the property most AI-agent frameworks miss entirely — an ACT_BOUNDED agent spawning an ACT_FULL child would silently defeat the whole tier system.
Circuit breaker with halt-as-evidenceLive
When a threshold trips, the agent halts and falls back to human review — and the halt itself is written to the ledger as evidence the control worked.
The halt is logged before fallback, so a regulator can see the safety mechanism firing rather than only its aftermath.
Multi-tenant isolation + OpenTelemetryLive
Each tenant's ledger is separate. Tracing runs VPC-internal with no prompt content leaving the perimeter.
Prompts and completions are never exported — gen_ai.* attributes stay isolated in the adapter layer, so observability doesn't quietly become a data-egress path.
These three are deliberately incomplete. The interfaces exist and the mechanisms around them work — the implementations behind them are placeholders, and shipping them as "done" would be the kind of undisclosed gap that costs a vendor its credibility on the first technical review.
Drift detectionDeterministic stubReal detector: Month 2
Returns a reproducible score so demos are stable, but it measures nothing real. The circuit-breaker mechanism it feeds is fully working — only the detection is placeholder.
adapters/drift/deterministic_stub.py. Production needs population stability index over a rolling reference window, plus semantic entropy for free-text outputs — which requires multiple sampled generations per call. That is a real latency and cost decision, not a weekend feature. Do not run Module 2 drift in production on this build; the stub will never trip.
Per-tenant HMAC keysFixed demo keyMonth 2
Currently one fixed key for every tenant. Enough to demonstrate chaining; not enough for real evidentiary separation between tenants.
Module 1 and Module 2 must chain with the same key or the chain breaks at the module boundary — so this is a key-custody design decision, not a one-line fix. Deferred deliberately rather than decided prematurely.
RFC 3161 timestampingLocal clockMonth 3
Timestamps are currently self-asserted from the system clock. Under adversarial cross-examination that is the weakest link in the chain, and we would rather say so than let a reviewer find it.
adapters/anchor/rfc3161_freetsa.py is designed but not implemented — it needs TSA selection, TLS, certificate validation, and outage handling. Until then, "when the root existed" rests on the bank's own clock.
PSI + semantic entropy drift detectorsNextMonth 2–4
Real drift measurement across data distribution, output semantics, and behaviour — replacing the stub behind the same interface.
Swapping is one branch in factories.py; nothing else in the system changes. That is the whole point of putting it behind a port.
DPDP Consent Manager integrationNextTracking Nov 2026
The Consent Manager framework under the DPDP Rules is being operationalised now, with the next enforcement phase in November 2026. Consent artefacts flow straight into the evidence ledger.
DPDP Rules 2025 were notified 14 Nov 2025 (G.S.R. 846(E)) with phased dates of 14 Nov 2025, 14 Nov 2026 and 14 May 2027 — this feature targets the second phase.
OPA / Rego policy enginePlannedMonth 3
Banks already standardised on Open Policy Agent will not adopt a bespoke rule language. This makes Praman fit their existing stack instead of replacing it.
Designed in docs/ADR/0004-policy-engine.md. The PolicyEngine port already exists, so this is a new adapter rather than a rewrite.
HSM / KMS signing pathPlannedMonth 3
Hardware-held keys. Most bank security teams will require this before any production sign-off.
The Signer port already abstracts this; the work is integration and key-ceremony documentation, not redesign.
Regulator verification portalExploringMonth 4+
A read-only view where an auditor pastes a certificate and independently verifies the root — without needing access to the bank's systems at all.
Verification only needs the public key and the root, so this can run entirely outside the bank's perimeter. That independence is what makes it persuasive.
